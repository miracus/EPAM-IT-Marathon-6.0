# Як здати проєкт на перевірку

## 1. Що вимагає марафон (зі вступної презентації)

| Рівень | Що потрібно | Що здавати |
|---|---|---|
| 1 | Скласти фінальний тест (examinator.epam.com, 30.10–04.11, одна спроба, 25 питань, 60 хв) | Нічого, результат фіксується автоматично |
| 2 | Розгорнути **наданий** репозиторій у хмарі | Унікальне посилання на застосунок |
| 3 | Реалізувати фічу в наданому коді та розгорнути | Посилання на **застосунок** + на **репозиторій** |

Анонси, домашні завдання й посилання для здачі публікують у **Telegram-спільноті марафону**. Точний спосіб здачі (Google Form, коментар у чаті тощо) дивись там. Ця інструкція готує все, що може знадобитися: публічний репозиторій, посилання на прототип і доступ до Figma.

> ДЗ T1 і T2 — це підготовка до рівня 3: User Stories і дизайн тієї фічі, яку потім реалізуємо в коді. Тому їх зручно тримати в тому самому GitHub-репозиторії, який потім піде на перевірку.

## 2. Що надсилати

1. **Посилання на публічний GitHub-репозиторій.** Це головне: перевіряючий бачить усе в одному місці, а README на головній сторінці пояснює структуру.
2. **Посилання на Figma з доступом «can view»**, бо дизайн-ДЗ дали саме у Figma.
3. За бажанням **посилання на живий прототип** через GitHub Pages. Його можна відкрити в браузері без завантаження файлів.

Не надсилай .docx чи .zip у чат, якщо про це прямо не просили. Посилання не застаріває, і його можна оновити без повторної здачі.

## 3. Створення публічного репозиторію на GitHub

### Варіант А — GitHub Desktop (найпростіше, без командного рядка)

1. Встанови GitHub Desktop (desktop.github.com) і увійди своїм акаунтом GitHub.
2. **File → Add local repository →** обери `D:\repos\EPUM\EPAM-IT-Marathon-6.0`.
3. Програма скаже, що це не репозиторій. Натисни **create a repository**:
   - Name: `EPAM-IT-Marathon-6.0`
   - Git ignore: None (файл `.gitignore` уже є в папці)
   - **Create repository**
4. Унизу ліворуч напиши повідомлення коміту, наприклад `T1 + T2 homework`, і натисни **Commit to main**.
5. Натисни **Publish repository** і **зніми галочку «Keep this code private»**. Після **Publish repository** репозиторій одразу стане публічним.

### Варіант Б — командний рядок (Git Bash / PowerShell)

1. На github.com: **+ → New repository** → назва `EPAM-IT-Marathon-6.0` → **Public** → нічого не додавай (без README, .gitignore і license) → **Create repository**.
2. У терміналі:

```bash
cd D:/repos/EPUM/EPAM-IT-Marathon-6.0
git init
git add .
git commit -m "T1 + T2 homework: user stories and group cart design"
git branch -M main
git remote add origin https://github.com/miracus/EPAM-IT-Marathon-6.0.git
git push -u origin main
```

Під час першого `git push` Windows відкриє вікно входу в GitHub. Увійди через браузер.

### Якщо репозиторій уже створено як приватний

На сторінці репозиторію: **Settings → General →** прокрути вниз до **Danger Zone → Change repository visibility → Change visibility → Make public**. Підтверди назву репозиторію, а GitHub може ще попросити пароль або 2FA.

Перевірка: відкрий посилання на репозиторій у вікні інкогніто. Якщо файли видно без входу, репозиторій публічний.

## 4. Живий прототип через GitHub Pages (за бажанням)

1. На сторінці репозиторію: **Settings → Pages**.
2. **Source: Deploy from a branch → Branch: `main` / `/ (root)` → Save**.
3. Через 1–2 хвилини прототипи стануть доступні за адресами:
   - `https://miracus.github.io/EPAM-IT-Marathon-6.0/T2/v3/` — актуальна версія з усіма функціями
   - `https://miracus.github.io/EPAM-IT-Marathon-6.0/T2/v2/`
   - `https://miracus.github.io/EPAM-IT-Marathon-6.0/T2/`

GitHub Pages для безкоштовного акаунта працює лише з **публічними** репозиторіями.

## 5. Доступ до Figma

Відкрий файл → **Share** (праворуч угорі) → **General access / Who has access → «Anyone with the link» → «can view»** → **Copy link**.
Перевір посилання в інкогніто. Файл має відкриватися без входу в Figma.

Якщо в Telegram просять здати саме у файлі марафону: відкрий файл марафону → **Duplicate to your drafts** → скопіюй фрейми з борду v3 (Ctrl+C / Ctrl+V) поруч з оригінальним «Cart – Owner & Guests Pre-Orders» → поділися посиланням на свою копію так само.

## 6. Перед тим як надсилати: чек-лист

- [ ] У репозиторії немає нічого робочого чи конфіденційного: паролів, рядків підключення, документів роботодавця. Публічний репозиторій бачить увесь інтернет.
- [ ] README на головній сторінці репозиторію відкривається й пояснює структуру.
- [ ] Посилання на репозиторій, Figma і Pages відкриваються в режимі інкогніто.
- [ ] Файли .docx відкриваються. GitHub не показує Word у браузері, але дає їх завантажити. Markdown-копія User Stories є в `T2/v3/USER_STORIES_v3.md`.
- [ ] Після змін зроби коміт і `push`. Посилання при цьому не змінюється.

## 8. Що буде далі (рівні 2–3)

Для рівнів 2 і 3 організатори дадуть **свій** репозиторій із кодом застосунку. Тоді правильний порядок такий:

1. **Fork** наданого репозиторію на свій акаунт (кнопка Fork). Fork публічного репозиторію теж публічний.
2. Реалізуй фічу в гілці, наприклад `feature/group-cart`, і злий її в `main` свого fork.
3. Розгорни у хмарі за інструкцією марафону.
4. Надішли посилання на застосунок і на свій fork.

Матеріали T1/T2 можна перенести в fork у папку `docs/`. Тоді код, вимоги й дизайн лежатимуть в одному місці.
